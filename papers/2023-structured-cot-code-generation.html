一句話總結

讓 LLM 先用循序、分支、迴圈結構寫出解題步驟，再依步驟產生程式碼。

研究問題

思維鏈提示（CoT）是當時最好的提示技術：先讓 LLM 用自然語言寫出推理步驟，再輸出答案。但 CoT 原本是為自然語言任務設計的，用在程式碼生成上效果很小，例如在 HumanEval 上只讓 ChatGPT 的 Pass@1 提升 0.82 分 p.1 p.2。

作者認為原因在於程式碼本身很有結構，任何程式都可以由循序、分支、迴圈三種基本結構組成，但 CoT 只是一句接一句地描述步驟，忽略了這些結構，迴圈的範圍也容易寫得模糊 p.1 p.2。所以本文想讓推理步驟本身就帶有程式結構，看能不能讓 LLM 寫出更正確的程式 p.2。

方法

  1. 提出結構化思維鏈（SCoT）：中間推理步驟必須用循序、分支（if / if-else / if-elif-else）、迴圈（for / while）三種基本結構來寫，結構之間可以巢狀 p.2 p.3。
  2. SCoT 開頭還要先寫出輸入輸出結構，也就是參數和型別，讓 LLM 先釐清需求和程式的進出口 p.2 p.3。
  3. SCoT 提示分兩步：第一個提示讓 LLM 依照範例產生 SCoT，第二個提示再根據需求和 SCoT 寫出程式碼。預設每個提示放 3 個範例 p.3 p.4。
  4. 為了避免 SCoT 本身的錯誤影響程式碼，第二步會要求 LLM 先檢查 SCoT 是否有錯；分成兩步也讓開發者有機會先修正 SCoT p.4。
  5. 在 ChatGPT（gpt-3.5-turbo-0301）和 Codex（code-davinci-002）上，用 HumanEval、MBPP（Python）和 MBCPP（C++）評估，指標是 unbiased Pass@k（k = 1、3、5），比較對象是 zero-shot、few-shot 和 CoT 提示 p.4 p.5。
AI 補充：SCoT 直接以 CoT 為基礎，把 CoT 的自然語言推理步驟換成接近虛擬碼的結構化步驟，可以看成 CoT 在程式碼生成上的改良版。

主要結果

  • 以 ChatGPT 的 Pass@1 來看，SCoT 相較 CoT 的相對提升為 HumanEval 13.79%、MBPP 12.31%、MBCPP 6.63%。在 Codex 上最多提升 13.77% p.6。
  • 人工評估中，10 位有 3～5 年經驗的開發者評分 800 個程式，SCoT 在正確性、code smell、可維護性三項都最高，相較 CoT 分別提升 15.27%、10.66%、15.90% p.6 p.7。
  • 換成不同的範例組合或不同撰寫者寫的 SCoT，表現都穩定高於 CoT，代表效果來自程式結構，不是特定範例 p.7 p.8。
  • 消融實驗中，拿掉三種基本結構後 HumanEval Pass@1 從 60.64 掉到 55.67；拿掉輸入輸出結構則掉到 59.65，代表基本結構的貢獻比較大 p.8。
  • 把中間步驟換成虛擬碼（SCoT-P）效果不如 SCoT。作者抽查 100 個 SCoT，26% 很接近虛擬碼，74% 比虛擬碼更抽象 p.9。

貢獻

  • 提出結構化思維鏈（SCoT），用程式結構來組成中間推理步驟 p.2。
  • 提出 SCoT 提示，讓 LLM 先產生 SCoT，再寫出程式碼 p.2。
  • 在三個基準測試上做了質化和量化實驗，SCoT 提示明顯優於 CoT 等方法 p.2。
  • 分析不同程式結構的貢獻，以及 SCoT 提示對範例的穩定性 p.2。

限制

  • 實驗結果的普遍性：只用了三個基準測試和 Python、C++ 兩種語言 p.10。
  • SCoT 分兩步生成，CoT 只有一步，提升可能來自兩步流程本身。作者用消融實驗回應：保留兩步流程但拿掉程式結構，效果明顯下降 p.10。
  • 資料洩漏：LLM 的訓練資料可能已經包含這些基準測試的題目。作者認為因為比較的是同一個模型上的相對提升，所以結論仍然可信 p.10。

名詞解釋

結構化思維鏈（Structured Chain-of-Thought, SCoT）
用循序、分支、迴圈結構，加上輸入輸出結構寫成的中間推理步驟，看起來介於自然語言和虛擬碼之間。
三種基本結構（Sequence, Branch, Loop）
循序是依序執行，分支是依條件走不同路線，迴圈是重複執行直到條件不成立。任何程式都可以由這三種結構組成。
Pass@k
每題讓模型產生 k 個程式，只要有一個通過全部測試就算解出，最後計算解出的題目比例。
HumanEval
常用的 Python 程式碼生成基準測試，有 164 題手寫題目，每題平均 7.7 個測試案例。
Code Smell
程式能跑，但寫法不好、之後容易出問題或難以維護的跡象。

我的心得

把推理步驟寫成接近虛擬碼的形式有助於提升 LLM 寫程式碼的準確度。
